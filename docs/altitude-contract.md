# Высоты в симуляторе

JSBSim и Cesium учитывают кривизну WGS84. Поверхность постоянной высоты — не глобальная касательная плоскость.

Обозначения: H — высота MSL, H0 — высота стартовой площадки, N — настроенная поправка геоида.

| Граница | Преобразование |
|---|---|
| DEM → физика | H земли; общий WorldElevation, включая выровненную ВПП |
| Мост → JSBSim terrain | (H земли − H0) / 0.3048, футы |
| JSBSim FDM → ArduPilot | fdm.altitude × 100 + home.alt, сантиметры |
| Поза JSBSim → мост | altitude + H0, метры |
| Мост → Cesium | H самолёта + N |
| DEM → сетка, деревья, здания | H земли + N |
| Старт, ВПП, точки миссии → Cesium | H0 + относительная высота + N |

AGL передаётся отдельно и не используется для восстановления абсолютной высоты ArduPilot. Иначе подъём земли на 100 м ошибочно опускал показание абсолютной высоты на 100 м.

После смены старта FDM-приёмник использует актуальную H0, а источник рельефа и terrain-feeder пересоздаются по поколению сессии.

`geoid_separation_m` — постоянная поправка для учебного района. Сейчас она равна нулю: поверхности внутри симуляции согласованы, но точность привязки к реальному геоиду EGM96 не заявляется. Для точной геодезической привязки больших территорий необходима локальная сетка геоида и пространственная поправка N(lat, lon), а не произвольное число.

За пределами загруженного DEM источник возвращает `fallback_elevation_asl_m`. Это резервная поверхность, а не реальные холмы. DEM Полтавы не покрывает выбранный старт в Херсонской области.

Сборка исправления: `python scripts/prepare_sitl_overrides.py`, затем штатный `scripts/build_sitl_docker.sh`. Патч монтируется только в сборочный контейнер; исходник в third_party не изменяется.
