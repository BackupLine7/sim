# Flight Lab

Local browser workstation: JSBSim + ArduPilot SITL + CesiumJS.

## Start on Windows

With Docker Desktop running and the previously built binaries present:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_simulator.ps1
```

Open http://127.0.0.1:8080. `-RestartBridge` reloads Python code while leaving
the flight running. The script refuses to terminate unrelated applications.

Полный цикл занятия:

1. **Рестарт · поставить на ВПП** — сброс физики, скорости и состояния
   автопилота; установка на ось ВПП 09 Полтава/Супруновка, курс 96.15°.
2. Дождитесь этапа **На ВПП**: ArduPilot должен подтвердить проверки перед
   включением двигателя. Обычно подготовка после рестарта занимает 20–30 секунд.
3. **Взлететь** — разбег и автоматический набор 120 м.
4. **Круг** или **Ручной режим** — полёт. W/S тангаж, A/D крен, Q/E газ;
   также доступны экранные кнопки и ползунок. Space включает LOITER.
5. **Посадить на ВПП** — ArduPilot AUTOLAND выполняет заход, снижение,
   выравнивание и пробег. Завершение фиксируется после остановки и disarm.
6. **Рестарт** начинает новое занятие с исходным состоянием.

**Вернуться к аэродрому** — RTL (возврат и круг), отдельная команда от посадки.
Ручное управление освобождается при уходе со вкладки. Наблюдающие вкладки
не посылают стики. Виды: 1 за самолётом, 2 из носа, 3 осмотр при автопилоте.

Позиция/курс/высота старта: `config/simulation.yaml`.
Размеры ВПП, параметры взлёта/посадки и таймауты: `config/airfield.json`.
После изменения конфигов перезапустите мост, затем нажмите рестарт самолёта.
Кэш изображений аэродрома воспроизводится `python scripts/prepare_world.py`.

## Included data and limits

The local Kyiv OSM map and 956 approximate extruded building footprints work
offline. Attribution and source data are in `web/data/README.md`. The aircraft
visual is an illustrative Cesium sample; JSBSim simulates the Rascal model.
This is a cartographic preview, not photoreal imagery. Buildings are visual,
not collision objects. The example still uses flat physics terrain. A surveyed
DEM, proper physical terrain integration, missions/instructor tools, and
five-seat endurance validation remain unfinished.

New screen control is limited to local SITL instance 0. Default demo commands
do not force arming; rejected arming is reported through autopilot messages.
The source example map covers a small central area, not the whole city.

## Карта, камера и режимы изображения (10 сентября 2026)

Камера по умолчанию расположена в носу; её оси вычисляются из положения JSBSim.
Положительный крен опускает правое крыло. Проверено на живом FBWA: вход +0.5
даёт около +26°, вход -0.5 около -27°; курс изменяется в соответствующую сторону.
Ошибочные знаки старого преобразования ориентации исправлены в нашем адаптере.

Кнопки над камерой: обычный вид, ночное видение, чёрно-белый тепловизор,
день/ночь. Сенсоры — визуальная имитация; температурная модель материалов
и объектов не реализована. День/ночь меняет видимость сцены, не погоду JSBSim.

Карта: `config/world.json`. Регион 30.4–40.5° E, 46–52.4° N охватывает восточную
Украину. Стартовая площадка — Полтава/Супруновка. Локально подготовлены 225 обзорных тайлов
z9 и 45 подробных z14 вокруг Киева, Харькова, Днепра, Полтавы, Краматорска.
В остальных местах подробный участок использует обзорное изображение: качество
ниже, это не подробный ортофотоплан всего региона. Во время занятия сеть выключена.

Подготовка: `python scripts/prepare_world.py`; повторный запуск пропускает готовые
файлы. `--detail` загружает ВСЮ область на уровне detail_level: большой набор,
не требуется для демонстрации. Снимки Sentinel-2 cloudless 2016, EOX IT Services
GmbH, CC BY 4.0: https://maps.eox.at/ и https://s2maps.eu.
Contains modified Copernicus Sentinel data 2016 & 2017.

Главный вид держит максимум 9 участков: изображения, здания и условные деревья
загружаются и удаляются вместе. При перелёте меняется набор участков. Мини-карта
имеет отдельный обзорный слой всего региона. Кнопка «Весь регион» показывает его.

«Осмотр · debug» доступен только на автопилоте. Голубые рамки показывают загруженные
участки; счётчики отображают загрузку, выгрузку, запросы и число деревьев. Мышью
можно отдалиться и осмотреть окружение. Камера не задаёт область подгрузки.
При переходе в ручное управление осмотр возвращается к камере из носа.

Деревья расставлены процедурно по цвету растительности, не по реальному реестру.
Здания доступны в прежнем примере Киева; рельеф пока плоский, столкновения
с этими визуальными объектами не моделируются.

## Текущий интерфейс и настройки

Вся сцена занимает область камеры. Управление, авиагоризонт и карта PiP находятся
поверх неё. Два списка выбирают положение камеры и режим изображения: обычный,
ночной зелёный, чёрно-белый и мягкий тепловизионный. Мягкий вариант имитирует
контраст, зерно и тёмное небо; это не расчёт температуры объектов.

Карта сохраняет центр на самолёте при масштабировании колесом и кнопками +/−.
Автомасштаб плавно увеличивает охват со скоростью, ручная поправка работает
совместно с ним. «Авто» отключает/возвращает автомасштаб; «На самолёт» возвращает
слежение после перемещения карты. Компас показывает север и возвращает ориентацию
на север по нажатию.

WASD и стрелки работают одновременно, Z/C — рыскание, Q/E — газ. Настройки:
инверсия и чувствительность трёх осей, минимальная/крейсерская/максимальная/
посадочная скорости, высоты взлёта и возврата, крен, ветер. Управление применяется
сразу, параметры автопилота — после рестарта. Скорость не ограничивается
искусственным зажимом физического состояния при пикировании.

Значения по умолчанию — config/preferences.json. Пользовательские значения
сохраняются атомарно в config/local.preferences.json; этот файл исключён из git.
API проверяет диапазоны, конечность чисел и порядок скоростей. Явное нажатие
режима передаёт управление текущей вкладке, старые стики больше не принимаются.

Размер модели больше не зависит от её размера в пикселях. Опорные точки нижней
поверхности извлечены из GLB скриптом scripts/prepare_aircraft_support.py;
у поверхности корректируется только положение визуальной модели. Физические
координаты, камера и управление берутся из JSBSim.

Учебный профиль шасси — отдельный TrainingAirframeAdapter, применяется к файлам
в build/jsbsim_root, исходники в third_party не меняются. Профиль связывает
управление хвостовым колесом с рулём направления для устойчивого пробега.
