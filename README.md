# Sim — тренажёр БПЛА самолётного типа

Физика JSBSim, автопилот ArduPilot SITL, картинка в браузере на CesiumJS.
Два вида одновременно: камера с борта и карта сверху. Работает офлайн —
снимки, рельеф и здания лежат на диске.

## Запуск

```
run.bat
```

Батник делает всё сам: проверяет инструменты, ставит библиотеки Python,
подтягивает `third_party/`, собирает JSBSim и ArduPilot в контейнере,
поднимает занятие и открывает страницу.

Первый запуск — 15–30 минут, из них почти всё это сборка. Повторный — полминуты:
собранное он пропускает.

Что нужно заранее:

| Что | Зачем |
|---|---|
| Python 3.12 | мост, подготовка данных, сам батник |
| Git | `third_party/` приходит субмодулями |
| Docker Desktop, запущенный | ArduPilot запускает JSBSim через `fork`, которого в Windows нет |
| Git Bash | только для первой сборки (`scripts/build_sitl_docker.sh`) |

Порты подбираются сами: берётся первая свободная пара начиная с 8080 — страница
на первом, поток позы на втором. Выбранный номер батник печатает и открывает,
страница узнаёт второй у моста через `/api/bridge`. Если вам нужен конкретный
порт, скажите заранее; занят чужой программой — запуск остановится с её именем
и PID, а не сделает вид, что всё хорошо.

Повторный `run.bat` гасит уже запущенный мост и поднимает новый — так
подхватываются правки кода. Физика и автопилот в контейнере при этом
продолжают полёт; картинка и ручное управление пропадают на несколько секунд.

```
run.bat                               порты выберет сам
set SIM_HTTP_PORT=8090 && run.bat     хочу именно этот (и 8091 под поток позы)
docker stop sim-sitl-0                остановить физику
```

Проверки без запуска занятия:

```
python run.py --check                 сойдутся ли настройки и высоты
python -m sim_bridge --replay         интерфейс без физики, полёт по кругу
set PYTHONPATH=src && python tests\test_world_tiles.py
node tests\test_world.mjs
```

## Границы: кто за что отвечает

Пять пакетов. Соседа каждый знает только по описанному здесь договору.

```
JSBSim ──UDP──> ArduPilot SITL ──MAVLink──> sim_bridge ──WS/HTTP──> браузер
   ^                                            │
   └──── TCP, высота рельефа ───────────────────┘   sim_world отдаёт участки мира
```

### `src/sim_world/` — мир

Отвечает на три вопроса про точку на карте: как она выглядит, какая под ней
земля, что на ней стоит. **Про симулятор, автопилот и физику не знает ничего.**

```
tiles.py              XYZ/Web Mercator: номер участка <-> градусы
imagery.py            снимки: кеш на диске, докачка, замена родительским тайлом
osm_tiles.py          фоновая качалка OSM: дома, дороги, деревья одним запросом
service.py            сборка участка из слоёв -> JSON для браузера
routes.py             HTTP-маршруты /api/world/*, /api/terrain-cache, ...
elevation/source.py   чтение DEM (GeoTIFF/HGT), билинейная выборка
elevation/streaming.py докачка плиток SRTM по ходу полёта
elevation/__init__.py  WorldElevation: высота точки и сетка высот участка
elevation/probe.py     «есть ли высота вот здесь и сейчас»
buildings/regions.py   постоянные областные выгрузки Overture в SQLite
buildings/__init__.py  BuildingLayer: местные + областные + скачанные, без дублей
vegetation/osm.py      деревья и аллеи из выгрузки OSM
vegetation/roadside.py придорожные посадки, детерминированно по seed
vegetation/__init__.py VegetationLayer: процедурные + OSM + придорожные
```

Договор с внешним миром — три вещи, которые ему **отдают снаружи**:

- `elevation` — любой объект с `elevation_asl_m(lat, lon)`, `grid(bounds)`,
  `geoid_separation_m`, `available`, `cache`;
- `exclude(lon, lat)` — где деревья ставить нельзя (у нас это ВПП);
- корень проекта с `config/*.json` и каталогом `data/`.

Ничего из симулятора внутрь не импортируется. Перенос в другой проект —
это копия папки плюс свои реализации этих трёх вещей.

### `web/world/` — мир в браузере

```
streamer.js        какие участки нужны, что качать, что выгружать. Cesium не знает
cesium-host.js     единственный файл, знающий про Cesium: собирает участок в сцене
layers/terrain.js  сетка рельефа с юбками по краям (стыки между уровнями)
layers/buildings.js коробки домов по контурам
layers/vegetation.js конусы деревьев
coverage.mjs       какие номера участков нужны вокруг точки
tile-keys.mjs      родитель/потомок, что показывать пока замена не догрузилась
outline.mjs        отладочная рамка по кромке участка
index.js           точка входа пакета
```

`WorldStreamer` общается с отрисовкой через `host`:

```js
host.cullingVolume()          -> {contains(сфера)} или null
host.createTile(data, canvas) -> {memory_bytes, boundingSphere,
                                  visible, setVisible(видно, отладка), destroy()}
```

Всё. Другой движок — пишется другой `host`, `streamer.js` не трогается.
Проверить пакет отдельно от тренажёра: `/world-preview.html`.

### `src/sim_bridge/` — мост

Склейка сервера и браузера, и всё, что относится к конкретному тренажёру:

```
__main__.py        приём позы по UDP, раздача по WebSocket, статус 30 Гц
static_server.py   HTTP: файлы страницы + маршруты, мировые отдаёт в sim_world
flight_control.py  MAVLink: режимы, взлёт, посадка, ручные стики
world.py           собирает WorldService: подставляет высоты и контур ВПП
world_elevation.py SimulatorElevation — высоты с выровненной ВПП
runway.py          геометрия ВПП: где ровнять землю, где не сажать деревья
missions.py        хранение и проверка полётных заданий
```

Здесь и только здесь мир встречается с симулятором.

### `src/sim_launcher/` — запуск

Поднимает пары SITL+JSBSim по числу учеников и подаёт в JSBSim высоту рельефа
по TCP-консоли 5–10 раз в секунду. Высоты берёт из `sim_world.elevation` —
тот же источник, что у картинки.

### `third_party/` — чужое

ArduPilot, JSBSim, CesiumJS на релизных тегах. **Править запрещено.** Нужно
другое поведение — наследник или обёртка в `src/`. Подробности в `CLAUDE.md`.

## Рельеф: один источник, два потребителя

Высоты живут в одном файле DEM. Физика читает их напрямую и пишет в JSBSim.
Браузер получает сетку высот, собранную из **того же файла**. Браузер никогда
не является источником высот для физики.

Меняете DEM — пересоберите и тайлы рельефа. Иначе физика летает по новому
рельефу, ученик смотрит на старый, и это никак не видно.

DEM обычно считает от геоида EGM96, Cesium — от эллипсоида WGS84. Расхождение
20–50 метров. `terrain.geoid_separation_m` в `config/simulation.yaml`; сверку
делает `python run.py --check`.

## Настройки

Всё, что зависит от полигона, железа или занятия, лежит в `config/`:

| Файл | Что задаёт |
|---|---|
| `simulation.yaml` | полигон, точка старта, порты, число учеников, DEM |
| `world.json` | границы региона, уровни тайлов, источник снимков, плотность деревьев |
| `airfield.json` | размеры ВПП, параметры взлёта и посадки |
| `terrain-streaming.json` | докачка высот: адрес, радиус, лимиты диска и памяти |
| `building-streaming.json` | докачка домов из Overpass |
| `building-regions.json` | областные выгрузки Overture |
| `osm-vegetation.json` | деревья и придорожные посадки |
| `preferences.json` | значения по умолчанию для настроек ученика |

`config/local.*` — то, что меняет пользователь; в репозиторий не попадает.

<https://s2maps.eu>, contains modified Copernicus Sentinel data 2016 & 2017.

Границы областей: [geoBoundaries](https://www.geoboundaries.org/).
Высоты: Mapzen Terrain Tiles / SRTM.

Деревья расставлены процедурно по цвету растительности, а не по реальному
реестру. Здания и деревья — визуальные, столкновения с ними не моделируются.
Режимы «ночь» и «тепловизор» — имитация картинки, а не расчёт температур.
